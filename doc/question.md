# 旅游助手 — 待完善功能清单

## 一、架构层面：多 Agent 协作未实现

**现状：** `planner.py` 将所有工具直接挂在单个 Agent 上（`create_react_agent`），是扁平的"单 Agent + 多工具"架构。

**设计预期：** 规划 Agent（M6）作为顶层调度者，将景点 Agent（M7）、路线 Agent（M8）、天气 Agent（M9）、预算 Agent（M10）作为子 Agent 调用，每个子 Agent 拥有独立的 LLM 推理能力和专属工具。

**具体问题：**

- `spot_finder.py`、`route_planner.py`、`weather_checker.py`、`budget_estimator.py` 文件已存在，但未被 `planner.py` 调度
- 子 Agent 文件使用了 `from langchain.agents import create_agent`，该 API 在 LangChain 中不存在，代码无法运行
- 缺少 Planner → 子 Agent 的调度机制（将子 Agent 包装为 LangChain Tool 注册到 Planner）

## 三、已有代码的质量问题

### 3.1 子 Agent 文件 API 调用错误

- `spot_finder.py` 和 `route_planner.py` 使用了 `from langchain.agents import create_agent`
- LangChain 中不存在 `create_agent` 这个函数，应使用 `langgraph.prebuilt.create_react_agent` 或其他正确的 API
- 这些文件写了但从未调试运行过

### 3.2 进度文档未更新

- `doc/tasks/progress.md` 中所有模块状态仍为 `[ ]`（未完成），与实际开发进度不符
- 各模块的任务文档（`doc/tasks/M01~M12`）未跟踪实际完成情况

## 四、优先级建议

| 优先级 | 功能 | 理由 |
|--------|------|------|
| P0 - 必须 | 修复子 Agent 并实现多 Agent 调度 | 课程核心考察点，架构设计的关键体现 |
| P1 - 重要 | 接入高德地图前端组件 | 视觉效果提升最大，旅游应用的核心交互 |
| P1 - 重要 | 行程导出 PDF | 设计文档明确要求，实现难度不大 |
| P2 - 一般 | 景点详情页 | 完善景点查询功能闭环 |
| P2 - 一般 | 天气/预算组件整合到行程页 | 提升行程详情页的信息完整度 |
| P3 - 可选 | 路线对比 | 锦上添花，非核心功能 |
