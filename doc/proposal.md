# 旅游助手 — 需求文档

## 1. 项目概述

### 1.1 项目名称

旅游助手（Travel Assistant）

### 1.2 项目性质

个人练手项目，用于学习和实践 Web 全栈开发与 LLM 应用集成。

### 1.3 项目简介

一个面向国内旅游场景的 Web 应用，帮助用户规划行程、查询景点、推荐路线。系统集成大语言模型（DeepSeek），通过对话式交互为用户提供智能行程规划、景点推荐和信息汇总服务，并结合地图展示、天气查询、预算管理等功能，提供一站式旅游规划体验。

### 1.4 目标用户

个人自用，面向有国内旅游规划需求的普通用户。

---

## 2. 技术选型

| 层级 | 技术 | 说明 |
|------|------|------|
| 后端框架 | FastAPI | Python 异步 Web 框架，自带 OpenAPI 文档 |
| 前端框架 | React | 前后端分离架构 |
| 数据库 | SQLite | 轻量级，无需额外数据库服务 |
| Agent 框架 | LangChain | LLM 编排框架，支持 ReAct 推理和多 Agent 协作 |
| Agent-工具协议 | LLM Function Calling | 通过 OpenAI 风格的 Function Calling 机制将工具暴露给 Agent |
| LLM 服务 | DeepSeek | 用于对话式行程规划、智能推荐、信息汇总 |
| 地图服务 | 高德地图 API | 景点定位、路线展示、地图交互 |
| 数据爬取 | 小红书 | 爬取旅游攻略和景点评价数据 |
| 包管理 | uv | Python 项目依赖管理 |

### 3.8 Agent 架构（LangChain）

系统采用 LangChain 框架构建多 Agent 协作架构，每个 Agent 使用 ReAct（Reasoning + Acting）模式进行多步推理和工具调用。

#### 3.8.1 Agent 角色定义

| Agent | 职责 | 可用工具 |
|-------|------|----------|
| 规划 Agent（Planner） | 接收用户的旅游需求，拆解为具体任务，编排行程方案 | 调用其他 Agent、行程模板生成 |
| 景点 Agent（Spot Finder） | 搜索和筛选景点信息，返回结构化景点数据 | 高德 POI 搜索、小红书数据查询、景点数据库检索 |
| 路线 Agent（Route Planner） | 根据景点列表规划最优游览路线和交通方式 | 高德路径规划 API、距离/耗时计算 |
| 天气 Agent（Weather Checker） | 查询目的地天气，评估天气对行程的影响 | 天气 API 查询 |
| 预算 Agent（Budget Estimator） | 估算行程费用，进行预算分配和控制 | 费用数据库查询、价格估算 |

#### 3.8.2 Agent 协作流程

```
用户输入: "帮我规划一个杭州3天2晚的旅行，预算3000元"
       │
       ▼
┌──────────────┐
│  规划 Agent   │  ← ReAct 模式：分析需求 → 拆解子任务 → 调度其他 Agent
│  (Planner)   │
└──────┬───────┘
       │ 并行/串行调度
       ├───────────────┬───────────────┬───────────────┐
       ▼               ▼               ▼               ▼
┌──────────────┐┌──────────────┐┌──────────────┐┌──────────────┐
│  景点 Agent   ││  天气 Agent   ││  路线 Agent   ││  预算 Agent   │
│ 搜索杭州景点  ││ 查询杭州天气  ││ 规划游览路线  ││ 估算总费用    │
└──────────────┘└──────────────┘└──────────────┘└──────────────┘
       │               │               │               │
       └───────────────┴───────────────┴───────────────┘
                              │
                              ▼
                    ┌──────────────────┐
                    │  规划 Agent 汇总  │
                    │  生成完整行程方案  │
                    └──────────────────┘
                              │
                              ▼
                        返回给用户
```

#### 3.8.3 ReAct 推理模式

每个 Agent 内部采用 ReAct 循环进行多步推理：

1. **Thought**（思考）：分析当前任务，决定下一步行动
2. **Action**（行动）：调用工具获取信息（如调用高德 API 搜索景点）
3. **Observation**（观察）：接收工具返回结果
4. **重复**：根据观察结果决定是否需要进一步行动，直到任务完成

## 4. 数据需求

### 4.1 景点数据

- **来源**：高德地图 POI 接口 + 小红书爬取
- **字段**：景点名称、所在城市、地理坐标、类型标签、简介、图片、评分、开放时间、门票价格、用户评价摘要

### 4.2 路线与交通数据

- **来源**：高德地图路径规划 API
- **字段**：起止点、途经点、距离、预计耗时、交通方式

### 4.3 天气数据

- **来源**：第三方天气 API（如高德天气或和风天气）
- **字段**：城市、日期、温度、天气状况、风力、降水概率

### 4.4 用户数据

- **存储**：SQLite 数据库
- **字段**：用户 ID、用户名、密码哈希、邮箱、创建时间、保存的行程列表

## 8. 技术架构要求

### 8.1 工具使用（Tool Use / Skills）

系统须为 Agent 配备至少 2 个独立的功能工具。本项目规划了 6 个工具，通过 LangChain 的 `@tool` 装饰器定义，并以 OpenAI 风格的 Function Calling 机制暴露给 LLM：

| 工具 | 类型 | 说明 |
|------|------|------|
| amap_poi_search | 外部 API 调用 | 调用高德地图 POI 搜索接口，获取景点信息 |
| amap_route_plan | 外部 API 调用 | 调用高德地图路径规划接口，获取路线和交通方案 |
| weather_query | 外部 API 调用 | 调用天气预报接口，获取目的地天气数据 |
| spot_db_search | 数据库查询 | 查询本地 SQLite 景点数据库 |
| xiaohongshu_search | 数据检索 | 查询已爬取的小红书攻略和评价数据 |
| budget_estimate | 本地计算 | 根据行程项目估算交通、住宿、门票等费用 |

### 8.2 上下文集成（Context Integration）

Agent 与工具之间采用 **LLM Function Calling** 协议进行集成：

- LangChain 将每个工具的名称、描述、参数 Schema（Pydantic 模型）注册到 LLM 的 function/tool 列表中
- LLM 在推理过程中自主决定是否调用工具、调用哪个工具、传入什么参数
- LangChain 负责解析 LLM 的 function call 响应，执行对应工具，并将结果回传给 LLM 继续推理

### 8.3 Vibe Coding 开发规范

本项目采用 "Vibe Coding" 模式，即借助 AI 编写基础设施代码，开发者专注于 Agent 的编排逻辑和 System Prompt 设计：

| 类别 | 方式 |
|------|------|
| AI 生成 | FastAPI 路由样板、Pydantic 数据模型、API 请求封装、数据库 CRUD、前端组件骨架 |
| 人工专注 | Agent System Prompt 设计、Agent 编排流程、工具调度策略、多 Agent 协作逻辑 |

## 9. 约束与风险

| 项目 | 说明 |
|------|------|
| API 额度 | 高德地图、DeepSeek 均有调用次数/费用限制，需注意控制调用频率 |
| 爬虫合规 | 小红书数据爬取需遵守 robots.txt 及平台规则，注意法律风险 |
| LLM 准确性 | 大模型生成内容可能存在事实错误，需在 UI 上给予提示 |
| 数据时效性 | 景点信息（门票价格、开放时间等）可能过时，需定期更新机制 |
